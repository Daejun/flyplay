초파리(*Drosophila melanogaster*) 전신 생체역학 시뮬레이터 **NeuroMechFly v2**를
이 컴퓨터에서 바로 돌릴 수 있도록 설치·검증하고, 두 가지 목적에 맞춘 스크립트를
준비해 두었습니다.

1. **실시간으로 초파리가 걷는 모습 보기** — 브라우저에서 직접 조종 (`scripts/09`)
2. **상황별로 초파리가 무엇을 학습하는지 보기** — 지형별 조향 학습 (`scripts/05~07`)

## 1. FlyGym이 무엇인가

| 항목 | 내용 |
|---|---|
| 저장소 | [NeLy-EPFL/flygym](https://github.com/NeLy-EPFL/flygym) (EPFL 신경공학 연구실, Apache-2.0) |
| 문서 | [neuromechfly.org](https://neuromechfly.org/) |
| 모델 | 실제 초파리 마이크로 CT 스캔 기반 전신 골격 + 근육/부착(adhesion) 액추에이터 |
| 물리 엔진 | MuJoCo (물리 시간 간격 dt = 1e-4 s, 즉 10 kHz) |
| 감각 | 겹눈(옴마티디아 721개 × 2), 관절각/속도, 다리 접지력, 몸통 자세 |
| 제어 계층 | 뇌 수준(하행 신호) ↔ 배신경삭 수준(CPG 보행 생성기)으로 분리 |

버전이 두 갈래인 점이 중요합니다.

- **FlyGym 2.x (여기 설치됨)** — 2026년 4월 전면 재작성. 빠르고, MuJoCo 대화형
  뷰어와 GPU(MJWarp) 배치 시뮬레이션을 지원합니다. **1.x와 API 호환되지 않습니다.**
- **FlyGym 1.x** — `flygym-gymnasium` 패키지로 이관
  ([문서](https://nely-epfl.github.io/flygym-gymnasium/)). 냄새 기둥(plume),
  연결체 기반 시각 처리, 경로적분 튜토리얼은 **아직 1.x에만** 있습니다.
  이 환경도 `.venv-v1`에 함께 설치해 두었습니다(§10).

**2.x에는 후각 센서 API가 없습니다**(패키지 전체 grep으로 확인). 그래서 1.x와 같은
센서 배치·같은 거리 역제곱 모델로 [flyplay/odor.py](flyplay/odor.py)에 직접
이식했습니다 — §5를 보세요.

## 4. 초파리가 "학습"하는 부분

### 무엇을 배우는가

정책은 **다리를 움직이는 법을 배우지 않습니다.** 보행 자체는 고정된 하이브리드
CPG 컨트롤러(= 배신경삭 모델)가 담당합니다. 정책이 배우는 것은 **하행 신호
(descending signal)** — 실제 초파리의 뇌가 배신경삭으로 내려보내는 좌/우 2차원
명령입니다.

```
관측 (목표가 내 기준 어느 방향인가, 내가 어떻게 움직이는가, 다리 상태)
   → 정책 →  [왼쪽 삼각보행 구동, 오른쪽 삼각보행 구동]
```

즉 학습 대상은 **조향 법칙(steering law)** 하나입니다. 작고 빨리 수렴하며,
무엇보다 **그림으로 그려서 확인할 수 있습니다.**

- **관측 34차원**: 목표 방위 cos/sin, 목표 거리, 전진/횡 속도, 요 각속도, 몸통
  높이, 몸통 기울기, CPG 위상 6개의 sin/cos, CPG 진폭 6개, 다리 접지 6개, 직전 행동
- **행동 2차원**: `[-1, 1]²` → 하행 신호 `[0.4, 1.6]²`
- **보상**: 목표까지 거리를 좁힌 만큼(주 항) + 목표를 향한 정도 − 명령 급변 페널티,
  도달 시 +50 / 넘어지거나 지형을 벗어나면 −20 후 종료

정의 전체는 [flyplay/env.py](flyplay/env.py)에 있습니다.

### 학습시키기

```bash
.venv\Scripts\python.exe scripts\05_train.py --terrain flat --steps 300000 --n-envs 6
```

이 PC에서 약 **340~370 env-steps/s** (6개 병렬)이고 300k 스텝에 **약 15분**입니다.
다만 평지 과제는 **8만 스텝(약 4분)이면 성공률 100%에 수렴**합니다.

| 스텝 | 평균 보상 | 성공률 | 평균 에피소드 길이 |
|---:|---:|---:|---:|
| 3k | −449 | 0% | 439 |
| 50k | −298 | 8% | — |
| 74k | +21 | 53% | 330 |
| 86k | +125 | 98% | — |
| 117k | +141 | 100% | 129 |
| 300k | +141 | 100% | 95 |

에피소드 길이가 439 → 95로 줄어든 것은, 초파리가 목표에 **더 빨리** 도달하게
되었다는 뜻입니다(에피소드는 도달 즉시 종료).

실제로 학습된 정책을 21개 방향에서 평가한 결과입니다.

```
reached the goal   : 21/21 episodes
time to goal       : 0.95 s (min 0.54, max 1.53)
steering gain      : +0.0112 signal per degree of bearing error
steering monotonic : rho = +0.913 over +-150 deg
turn command at -90/0/+90 deg: -0.82 / +0.01 / +0.96
=> learned a clean 'turn toward the goal' law.
```

−90°에서 −0.82, 0°에서 +0.01, +90°에서 +0.96 — **원점을 지나는 반대칭 곡선**입니다.
초파리가 "목표 쪽으로 돌아라"라는 법칙을 정확히 학습했다는 뜻입니다.

진행 상황은 텐서보드로 볼 수 있습니다.

```bash
.venv\Scripts\tensorboard.exe --logdir out/rl/tb
```

지형을 바꿔가며 여러 개 학습시키면 "상황에 따라 무엇이 달라지는가"를 비교할 수 있습니다.

```bash
.venv\Scripts\python.exe scripts\05_train.py --terrain blocks --steps 400000
.venv\Scripts\python.exe scripts\05_train.py --terrain gapped --steps 400000
```

3. **방위별 성공/소요시간** — 어느 방향을 잘하고 어느 방향을 못하는가
4. **한 에피소드 전개** — 방위 오차와 좌/우 하행 신호의 시간 변화(피드백 루프)

## 5. 냄새 + 시각 다중감각 과제 ★

논문 Figure 5에 해당하는 과제를 2.x API 위에 다시 구현했습니다. **FlyGym 2.1.0에는
후각이 없어서 직접 이식했습니다**([flyplay/odor.py](flyplay/odor.py)).

### 왜 두 감각이 모두 필요한가

- **냄새는 "어디"만 알려줍니다.** 세기가 거리 역제곱으로 퍼지는 방사형 장이라,
  먹이 방향은 가리키지만 앞을 막은 것은 모릅니다.
- **시각은 "무엇이 막고 있는지"만 알려줍니다.** 기둥은 어둡고 잘 보이지만,
  먹이에는 시각 표지가 전혀 없습니다(마커 geom을 group 2에 두어 겹눈 렌더러가
  무시합니다 — 실제로 먹이를 눈앞에 둬도 시각 특징이 0.0000만큼도 변하지 않음을 확인).

관측에는 **목표 방위도 거리도 주지 않습니다.** 먹이에 대해 아는 것은 전부 후각 센서
4개를 통해서만 들어옵니다. ([flyplay/env_multimodal.py](flyplay/env_multimodal.py))

### 손으로 만든 제어기로 먼저 확인한 것

학습 전에 과제가 풀리는지, 그리고 정말 다중감각인지 검증했습니다.

| 제어기 | 기둥 | 먹이 도달 | 충돌 스텝 | 평균 소요 |
|---|---:|---:|---:|---:|
| 직진 | 0 | 0/8 | 0 | — |
| **냄새 주화성** | 0 | **8/8** | 0 | 1.50 s |
| 직진 | 2 | 0/8 | 37 | — |
| **냄새 주화성** | 2 | **3/8** | **134** | 2.24 s |

**두 감각이 서로를 대체할 수 없다는 것이 수치로 확인된 셈**이고, 이것이 RL 정책이

## 6. 버섯체 후각 조건화 ★

지금까지의 학습은 전부 PPO였습니다 — 진짜 몸과 진짜 감각기에 MLP 뇌를 붙인 것입니다.
여기서는 그 뇌 자리에 **버섯체**를 넣습니다. 초파리가 냄새와 결과를 짝짓는 회로이고,
FlyGym에는 없습니다.

```
냄새 (2차원) → ORN 50종 → 촉각엽 → 케니언 세포 2000개 (5% 활성)
                                        ├→ MBON 접근 ┐
                                        └→ MBON 회피 ┘→ 가치 → 조향 부호
                         도파민: 켜져 있던 KC의 시냅스만 약화 (구획별로 독립)
```

학습되는 것은 **케니언 세포 → MBON 시냅스뿐**이고 강화학습은 없습니다. 조향은
손으로 만든 주화성 규칙이고, 버섯체는 그 부호와 크기를 정합니다. 처음 보는 냄새에
대한 끌림은 버섯체가 아니라 외측각이 담당하므로 고정값(0.35)으로 더합니다.

### 과제가 왜 조건화인가

버섯체는 조향 제어기가 아니라 **연합학습** 회로라서, 먹이찾기 과제에 그대로 끼워
넣으면 아무것도 배우지 않습니다. 그래서 실제 초파리 연구의 T-maze와 같은 과제로
바꿨습니다.

1. **순진 시험** — 두 냄새를 좌우에 두고 어느 쪽으로 가는지. 0 근처여야 합니다
2. **훈련** — 냄새 A 하나만, 그 속에 머무는 동안 도파민(벌)
3. **시험** — 다시 두 냄새, 벌 없음. A를 피하면 선호도 +
4. **역전 훈련** — 이번엔 B에 벌
5. **시험** — B를 피하면 선호도 −

버섯체 가중치는 시행을 넘어 유지되고 물리만 매 시행 리셋되므로, 이것은 `gym.Env`가
아니라 **실험 러너**입니다([flyplay/conditioning.py](flyplay/conditioning.py)).

### 실행

```bash
.venv\Scripts\python.exe scripts\13_mb_check.py
```

회로 검증 12항목입니다(몸 없이, 몇 초). KC 부호가 농도에 불변인지, 두 냄새를
분리하는지, 도파민이 짝지어진 냄새만 누르는지, 다른 구획으로 새지 않는지, 기억이
복원되는지, 전역 도파민 하나로는 두 냄새를 구별할 수 없는지 확인합니다.

```bash
.venv\Scripts\python.exe scripts\14_run_conditioning.py
.venv\Scripts\python.exe scripts\15_analyze_mb.py
```

3조건(구획 2개 / 전역 도파민 1개 / 가소성 없음) × 5마리 × 58시행을 병렬로 돌리고
(16코어에서 8.6분) 표와 4분할 그림(`out/analysis/mushroom_body.png`)을 만듭니다.

```bash
.venv\Scripts\python.exe scripts\09_web_viewer.py --conditioning --port 8010
```

한 마리가 배우는 과정을 실시간으로 봅니다(§3의 조건화 모드 패널).

### 결과

| 조건 | 순진 | A에 벌 준 뒤 | B로 역전한 뒤 | 가치 분리 |
|---|---:|---:|---:|---:|
| 구획 2개 | −0.05 ± 0.07 | **+0.49 ± 0.02** | **−0.30 ± 0.01** | +0.392 |
| 전역 도파민 1개 | −0.05 ± 0.07 | +0.01 ± 0.13 | −0.04 ± 0.05 | **0.000** |
| 가소성 없음 | −0.05 ± 0.07 | +0.01 ± 0.13 | −0.04 ± 0.05 | **0.000** |

선호도 +1은 B 쪽, −1은 A 쪽. 오차는 개체 간 표준오차(n=5).

- **학습됩니다.** A에 벌을 주면 5마리 모두 B 쪽으로(+0.44~+0.52) 갑니다.
- **구획이 필요합니다.** 도파민 신호가 하나뿐이면 가치 분리가 **정확히 0**입니다.
  두 구획이 같은 신호와 같은 세포를 받아 가중치가 갈라질 수 없기 때문입니다.
  시냅스가 안 바뀌는 게 아니라 오히려 더 깊게 눌리는데(접근 MBON 최저 0.02~0.03,
  기준 조건은 0.45~0.52), 회피를 못 배워서 **벌을 계속 맞기 때문**입니다.
- **배우면 벌을 덜 맞습니다.** 훈련 시행당 도파민이 기준 조건은 첫 5시행 0.76초
  → 마지막 5시행 0.21초로 줄고, 전역 도파민 조건은 2.25초 → 2.45초로 끝까지
  줄지 않습니다. 선호도가 채점하지 않는 훈련 시행에서도 학습이 행동으로 보입니다.
- **수동적 망각만으로는 역전이 약합니다.** 5마리 모두 부호는 뒤집히지만 −0.30에
  그칩니다. 역전 시험 때 A의 기억이 15% 남아 있기 때문입니다.

### 소거를 넣으면

벌을 예상한 냄새에 벌이 오지 않으면 MBON 출력이 도파민 뉴런을 구동해 `avoid`
구획을 누르는 **능동적 소거**를 넣었습니다(Felsenberg et al. 2018). 벌 있는 시행과
없는 노출을 번갈아 주는 차등 조건화로 세 조건을 비교합니다.

```bash
.venv\Scripts\python.exe scripts\14_run_conditioning.py --experiment extinction
.venv\Scripts\python.exe scripts\15_analyze_mb.py --dir out\mb_extinction
```

| 조건 | 획득 후 | 역전 후 | 대칭성 |
|---|---:|---:|---:|
| 소거 없음 | +0.49 | −0.30 | 0.61 |
| **소거 → avoid** | **+0.48** | **−0.50** | **1.04** |
| 소거 → approach (잘못된 배선) | −0.01 | +0.06 | — |

- **역전이 획득만큼 강해집니다.** 소거 없는 대조군은 원래와 똑같이 −0.30입니다.
- **원래 기억은 그대로 있습니다.** A에 대한 approach 반응은 소거가 있든 없든
  0.872로 같고, avoid만 내려와 상쇄합니다. 지우는 게 아니라 맞서는 기억을 더합니다.
- **잘못 연결하면 공포가 번집니다.** 같은 신호를 approach로 보내면, A와 케니언
  세포를 조금 공유하는 B의 작은 혐오(−0.004)가 노출마다 두 배로 불어나
  −0.65가 됩니다. 한 번도 벌받지 않은 B가 벌받은 A보다 더 무서워집니다.

자세한 분석은 [RESEARCH.md](RESEARCH.md) 10번.

### 기억 저장과 불러오기

실험은 초파리마다 블록이 끝날 때 시냅스를 저장합니다. 보관할 것은 이름을 붙여
`memories/`에 둡니다 — `out/`과 달리 실험을 다시 돌려도 덮어써지지 않습니다.


| 기억 | 가치 A | 가치 B | 무엇을 보게 되나 |
|---|---:|---:|---|
| `naive` | 0.000 | 0.000 | 아무것도 모름. 비교 기준 |
| `a-punished` | −0.507 | −0.007 | A를 피해 B로 감 |

보관하고, 코드에서는 `flyplay.conditioning.experiment_from_memory`로 불러옵니다.

## 8. 지형 설정에서 손본 부분

FlyGym 기본값을 그대로 쓰면 지형 3개가 실패해서 수정했습니다. 이유는
[flyplay/build.py](flyplay/build.py)에 주석으로 남겨 두었습니다.

- **`gapped`** — 기본 스폰 높이(0.9 mm)면 첫 걸음에 발끝이 틈에 빠져 뒤집힙니다.
  1.2 mm로 올리면 정상 보행합니다. 또 기본 지형은 x=25 mm에서 끝나는데 초파리가
  3초면 통과해 버려서 45 mm로 늘렸습니다.
- **`blocks`** — `BlocksTerrainWorld`에는 **블록 아래에 바닥이 없습니다.** 패치를
  벗어나면 허공으로 떨어지며 굴러서, 보행 실패처럼 보이지만 사실은 낙하입니다
  (2.05초에 z가 −344 mm로 급락하는 것을 확인). 블록 밑면 높이(z=0)에 평면을
  깔아서 "작은 계단을 내려서는 것"으로 바꿨습니다. 단차도 0.35 mm → 0.15~0.25 mm로
  낮췄습니다(0.35 mm에서는 3초에 5 mm밖에 못 가서 RL 목표에 도달 자체가 불가능).
- **`mixed`** — 구간을 하나 더 붙여 32 mm까지 늘렸습니다.
- **접촉 바디** — 모든 지형에서 `TIBIA_TARSUS_ONLY`를 씁니다. 몸통/머리까지
  포함하면 접촉쌍이 (파리 지오메트리 × 지형 지오메트리)로 늘어 모델 빌드 시간이
  2배가 되는데(67초 → 113초), 몸통은 지면에서 1 mm 떠 있고 여기 최대 단차는
  0.45 mm라 결과는 같습니다.

RL 환경의 낙하 판정도 고쳤습니다. 초파리는 공중에서 스폰되어 안정화에 0.2초가
걸리는데, 그 전에 기준 높이를 재면 보행 중 정상적인 몸통 상하 진동(±0.2 mm)이
낙하로 오판되어 **평지에서도 모든 에피소드가 0.1초 만에 종료**되었습니다.
안정화 후 몸통 높이의 중앙값을 기준으로 삼고, 임계값을 0.8 mm로 두었습니다.

검증: 직진만 하는 정책은 6번 중 0번 도달(보상 −99), 단순 비례 조향 정책은
6번 중 6번 도달(보상 +141). 보상 함수가 의도대로 구분합니다.
